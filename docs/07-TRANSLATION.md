# 转译 · 小鸟做的那件多余的事

## 为什么这一步值钱

吸引力法则要两件事:**说得具体**,和**相信**。

第二件产品已经解决了 —— 三分钟音频用你自己的话、现在时讲出来,那就是建立相信的机制。

第一件一直空着。用户说"我想要有钱",这句话既带不动生成,也带不动显化。

所以这一步同时干三件事:

1. **给小鸟一个真正的职业。** 只负责运输的信使是一根管子。会帮你把话说对的信使,是一个有本事的角色 —— 它飞过一百万次,它知道天上听得进什么。
2. **修掉生成质量的头号杀手。** 模糊输入 → 通用输出 → "这跟我没关系" → 流失。
3. **造出全产品唯一的双向时刻。** 其余所有交互都是单向的:你说、它生成、你听。这里是它回话。

---

## 你提的两个方案,各有一个坑

### 方案一:提交时拦下来说"太不具体了"

**坑:这是老师的语气。**

整个产品的承诺是「说出来,你会被听见」。她说完了,然后我们回一句"不行,重说" —— 这是对核心承诺的背叛。而且吸引力法则本身要求"相信",一个刚被否定的人建立不了相信。

### 方案二:转译时直接帮她改具体,再问 OK 不 OK

**坑:这违反了「回来的是你自己的话」。**

她说"我想要有钱",小鸟改成"我想在 2027 年底前存下 20 万" —— 这不是她的话,也未必是她的真实想法。她很可能出于客气点了 OK,然后**整个长期画像建立在小鸟的编造之上**,后面每天的音频都在念一个她并不真想要的东西。

而且这一步一旦自动化,她下次就不会自己说具体了 —— 反正小鸟会补。

---

## 建议:不否定,不代写,只是提议

> **小鸟从不说「太模糊」。它说:「这个我能带。但我知道 ___ 的话,能飞得更远。」**

三条规则:

**一、永远不拦。** 「就按我说的带上去 →」这个出口必须一直在,而且不能做得像放弃。她说了算 —— 被否决的人建立不了相信。

**二、不代写句子,只提供选项。** 而且**选项来自她自己已经说过的东西**,不是小鸟凭空生成的。这是 21 屏 onboarding 的兑现时刻 —— 它终于用上了。

**三、只出现一次。** 每次会话最多提议一次。她拒绝两次之后,记住,别再提。

### 一个例子

```
她说:  I want to have money.

小鸟:  I can carry that.
       It flies further if I know what it looks like.

       ┌ 从她 onboarding 里说过的话来 ┐
       + Enough that rent week isn't a week
       + Leaving the job without a plan B
       + The house, eventually
       └─────────────────────────────┘

       Take it as I said it  →
```

选项是**加上去**的,不是**换掉**原句。最后带上去的是:
`I want to have money — enough that rent week isn't a week.`

前半句还是她的。

## 交互形态:校对符号

放在**转写确认那一屏(15b)**,不是提交时。她那时已经在看一个可编辑的框,加东西不突兀。

具体做法:**把模糊的那个词标出来,像编辑在稿子上画的记号。**

```
I want to have  m̲o̲n̲e̲y̲
                 ╰── 珊瑚色波浪下划线,点开出选项
```

三个理由:

- **它不是判断,是指认。** 一条下划线没有语气,"太模糊了"有。
- **它跟整套视觉是一路的。** 我们做的是复古印刷 —— 校对符号、红笔批注,本来就长在这套语言里。
- **它是可忽略的。** 不弹窗、不拦截,不理它直接点「That's it」就走了。

---

## 什么算够具体(工程需要一条线)

**只要有以下任意一项就放行:**

| 锚点 | 例子 |
|---|---|
| 时间 | tomorrow · Thursday · by spring · in three years |
| 人或地点 | Daniel · the big room · my mum's kitchen |
| 可观察的行为 | 不在开口前先道歉 · 讲话慢下来 · 先挂电话 |
| 感官细节 | 它成真的时候，听起来 / 看起来 / 摸起来是什么样 |

**一项都没有 → 提议。**

### 这条线上最容易犯的错

**不要把「具体」等同于「近期」,也不要要求日期。**

> "我想成为不会在开口前先道歉的人"

没有时间、没有地点,但它**极其具体** —— 它描述了一个可观察的行为。这句话鸟带得很远。

如果检查器强制要求时间锚点,它会把这类最好的愿望判成不合格。这是这个功能最可能翻车的地方。

---

## 文案规则

**不要用:**
too vague · be more specific · try again · that won't work · the universe needs details

**要用:**
I can carry that · it flies further if · I'll know where to put it if · tell me one more thing

区别在于:前者说**你说错了**,后者说**我想做得更好**。同一个功能,两种人格。

---

## 触发规则

| | |
|---|---|
| 每次会话最多 | 1 次 |
| 连续拒绝 2 次后 | 停止提议,记进画像 |
| 平常日子那条路(选状态) | **不触发** —— 状态不需要具体 |
| 用户主动点「帮我说得更清楚」 | 随时可用,不计入上限 |

最后一条值得单独做一个入口。**主动求助和被动纠正是两种完全不同的体验** —— 同样的功能,她自己按的时候是工具,我们弹出来的时候是批评。

---

## 还没定的

- **提议的选项从哪儿来?** 我的建议是优先从她 onboarding 和历史里说过的原话检索,检索不到再生成。原话优先,这跟音频脚本的原则一致。
- **"相信"那一半要不要也做?** 目前靠三分钟音频。如果这个转译层做成了,可以考虑在带上去之后加一个极短的确认动作(按住三秒之类)—— 但这是后话,先别加。
